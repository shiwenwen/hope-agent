## 9.1 子 Agent

主 Agent 可以把一个独立子任务派给另一个(或同一个)Agent 在**隔离会话**里异步执行,完成后结果自动回流到当前对话,让主 Agent 接着往下做。这一切由 AI 自主发起,你不用手动操作,但可以在设置里管控。

- **前台等待**:默认等 30 秒,超时未完成会自动转入后台继续跑,不阻塞你的对话。
- **批量派发**:一次并行派多个子任务,全部完成后合并成一条汇总一次性注入(省一轮成本)。
- 运行中可以引导(推送提示)、取消单个或全部。
- 子 Agent 默认在独立的[隔离工作树](07-工具与权限.md#79-文件操作git-与隔离工作树)里跑,不污染你的主工作区。

**查看运行情况**:对话里每个子 Agent 显示为一枚胶囊(头像、名称、状态、耗时),点击打开右侧「子智能体」面板。

- 列表按**运行中 / 已完成**分组,涵盖本会话全部子 Agent——前台、后台,以及 Workflow 派生的都在内。同一个子 Agent 被继续执行时仍显示为一项,并标出累计运行次数。
- 点进某一个,可以看它的**结果**、**调用信息**(服务商、模型、思考强度、起止时间、附件、嵌套深度等)、**实时对话**和历次运行时间线;已完成的默认落在结果,运行中的默认落在对话。
- 如果应用退出或进程异常中断,当时正在执行的子 Agent 会显示为 **Interrupted**,不会被静默重跑。主 Agent 或 Workflow 可以显式继续同一个子 Agent:保留它已有的会话与工作目录,但创建一次新的运行;用户主动取消的运行不会自动恢复。
- 子 Agent 自己再派的下一层可以继续点进去,用面包屑逐级返回。
- 工作台里也有「子智能体」区块,列出同一份清单。

**设置**(在 Agent 编辑页 → 子 Agent 调用 标签):

| 设置项 | 默认值 | 作用 |
| --- | --- | --- |
| 启用子 Agent | 开 | 该 Agent 是否可派子 Agent |
| 允许的子 Agent | 全部 | 勾选哪些 Agent 可被当子 Agent |
| 最大嵌套深度 | 3 | 子 Agent 再派子 Agent 的层数(1–5) |
| 最大并发 | 8 | 单会话同时运行的子 Agent 上限 |
| 默认超时 | 0(不超时) | 子 Agent 执行超时秒数 |

> 你新发的消息优先级高于自动注入——一发消息就会取消在途注入,注入排队到空闲后重试(不丢结果)。后台子 Agent 会投影进统一的[后台任务面板](#93-后台任务面板)。

## 9.2 Agent 团队

团队让多个具名 Agent 作为成员**并行协作**——成员之间可以互发消息、共享一块看板任务,由协调者统一编排。这区别于子 Agent「父派子、子回收」的单向模式。

**怎么用**:

- 由 AI 调用 `team` 工具创建(用团队模板一键铺开成员),或用 `/team` 命令管理。
- **模板在设置里预配**:设置 → 团队,添加 / 编辑模板,每个模板定义成员的名字、绑定的 Agent 和角色。
- 团队运行时右侧会弹出团队面板,有三个标签:仪表板(成员卡片 + 进度 + Token 统计)、任务(待办 / 进行中 / 审查 / 完成四列)、消息(实时消息流,可手动给团队发消息)。

**设置**(在 Agent 配置里):是否允许创建团队、最大活跃团队数(默认 3)、每团队最大成员数(默认 8)、成员默认模型。

> 目前**没有内置团队模板**,全部由你在设置里自定义。模板引用的 Agent 被删除后,创建团队时会报错。

## 9.3 后台任务面板

所有异步 / 后台执行的工具、子 Agent、批量任务统一进一张面板,可以实时看状态、看运行输出、随时取消。

- **入口**:聊天头部的徽标、独立面板,以及工作台里的后台任务区块。
- 后台执行命令时可以实时看到输出「尾巴」,判断是「还在跑」还是「卡住了」。
- 任务完成后可以发桌面通知(默认开)。

哪些工具能后台运行:执行命令、浏览器、网络搜索、AI 画图、音频生成、应用更新。

**设置(设置 → 工具设置 → 异步工具,中风险)**:

| 设置项 | 默认值 | 作用 |
| --- | --- | --- |
| 启用异步工具 | 开 | 后台化总开关 |
| 自动转后台阈值 | 0(关) | 同步工具跑超过此秒数自动转后台 |
| 完成合并窗口 | 3 秒 | 同会话多个任务在窗口内完成合并为一轮注入(省成本) |
| 全局并发上限 | 8(按核数) | 所有会话的后台任务并发数 |
| 每会话并发上限 | 6(按核数派生,恒小于全局) | 单会话后台任务并发数,超出排队 |
| 失败自动重试 | 关 | 仅对无副作用的工具(如网络搜索)重试;执行命令 / 画图等永不重试 |

## 9.4 定时任务(Cron)

让 AI 按计划自动跑一段对话。它既可以为每次运行新建普通对话,也可以把任务排进一个已有对话;结果还可以发桌面通知,或投递到指定的 IM 会话。

### 创建方式

- **使用模型创建**:定时任务面板 → 新建任务。点主按钮或在箭头菜单中选「使用模型创建」,会回到普通对话并在输入框放入一句口语化引导;补上时间和要做的事,发给模型即可。模型既能创建「新对话」任务,也能按你的明确要求「安排当前会话」。
- **手动设置**:在新建任务的箭头菜单中选「手动设置」,再填名称、调度、消息、Agent、工作区和投递目标等。默认每次运行新建一个普通对话;在「运行位置」里改选「已有会话」,可以搜索并选择任意一个普通对话作为目标。
- **安排当前会话**:在普通会话标题栏点击计时器图标「安排当前会话」。目标会话会锁定为当前会话,不需要重新选择 Agent 或项目。

也可以直接在普通对话里对模型说:「1 分钟后在这个会话里提醒我继续测试」或「每天上午 9 点在‘网站改版’那个对话里总结进展」。前者直接绑定当前会话;后者会先查找已有会话,再用精确的会话 ID 创建任务,不会按标题猜测。普通的「提醒我」默认仍会创建独立的新对话任务。

### 选择运行位置

| 位置 | 运行方式 | 适合 |
| --- | --- | --- |
| 新对话 | 每次触发创建一个以任务名为标题的普通对话 | 独立日报、巡检、需要长期保留每次完整记录的任务 |
| 已有对话 | 把每次运行作为只读的 Scheduled 消息排入同一对话;「安排当前会话」是其快捷入口,手动设置里也可以搜索选择别的对话 | 需要持续共用同一上下文、项目、知识空间、Worktree 或工作目录的任务 |

运行位置在任务创建后不可更改;要换一个对话,请新建任务。

新建的运行对话会正常出现在主侧边栏、搜索、置顶、归档和普通未读里,不是隐藏的 Cron 专用会话。任务触发徽标会把消息和来源任务连起来。

任务绑定已有会话时,系统在真正轮到它执行的那一刻读取该会话**当前**的 Agent、模型、项目、知识空间、工作目录、权限和沙箱设置。任务不会复制或临时覆盖这些设置;如果你之后修改了会话配置,下次运行会跟随新配置。

### 调度类型与时区

| 类型 | 说明 |
| --- | --- |
| 一次性(At) | 指定日期时间触发一次 |
| 固定间隔(Every) | 每 N 分 / 时 / 天触发(下限 1 分钟) |
| cron 表达式(Cron) | 标准 cron,GUI 有可视化构建器;带 **IANA 时区选择器**,默认填你的浏览器时区,按该时区的墙上时钟解释、支持夏令时 |

### 保存或立即运行前的检查

创建、编辑或点击「立即运行」前会先出现预检。它最先展示这次会运行在哪个对话(新对话,还是某个具体的已有对话及其当前标题),然后是接下来 3 次触发时间,以及实际使用的 Agent、主模型、项目、工作区模式 / 基准分支、工作区改动文件数、权限和沙箱;投递目标逐条列出并标明各自的问题;最后还会显示调度器是否为主进程、当前正在运行的任务数,以及这个任务本身是否正在运行。

- **阻断项**不能强行继续。常见原因有目标对话不可用、归档 / 缺失的受管项目、基准分支无效、Persistent Worktree 正忙或冲突、模型未配置、IM 账号 / 会话失效,以及远程写入被禁用。
- **警告项**可以确认后继续,但应先看清影响。
- 如果别人或另一个窗口刚修改过任务,会显示版本冲突并保留你的草稿。只有你明确加载最新版本后才会替换字段,不会用旧草稿静默覆盖新配置。

### 工作区模式

仅「新对话」任务可以选择任务级工作区;绑定已有对话的任务始终跟随目标对话正在使用的工作区。

| 模式 | 行为 | 运行后的处理 |
| --- | --- | --- |
| Project | 直接使用项目工作目录 | 最简单,也会看到该目录中的现有改动 |
| Fresh | 每次运行从可选 Base ref 创建一个隔离 Git Worktree | 每次结果独立保留;可按界面给出的操作归档、恢复或丢弃 |
| Persistent | 任务长期持有一个 Git Worktree,后续运行反复使用 | 每个运行对话都保留该 Worktree,打开后可像普通对话一样继续使用;需要独占修改时可接管并暂停任务 |

Fresh / Persistent 需要选择 Git 项目。Base ref 留空时使用 `HEAD`;预检会验证它能解析为提交。后端会根据 Worktree 的真实归属、运行状态、冲突和会话占用情况决定哪些操作可用,读取失败时不会猜测放行。即使任务已删除,尚未处理的 Persistent / retained Worktree 仍会在定时任务页面的待处理资源区出现。

运行结束不会从对话中卸载 Worktree。之后从消息列表或运行历史打开该对话,标题栏、文件区和工具执行仍使用本次运行的 Worktree 路径,与普通 Worktree 对话一致。

自然语言创建也支持这三种模式。例如可以说「在项目 X 的 Fresh Worktree 中,从 `main` 开始,每天检查依赖更新」,或「给项目 X 建一个 Persistent Worktree,每小时继续修复测试」。AI 会先查 Project,再把 Worktree 模式和 Base ref 写入任务并走与表单相同的预检;无效分支、非 Git Project、忙碌 / 冲突的 Persistent 资源会直接阻断。你也可以让 AI「查看这个定时任务的工作区状态」或在资源尚未创建 / 占用时修改模式和 Base ref。

AI 创建成功后,回复中会挂出定时任务卡片。卡片显示当前状态、排程、下次运行与 Worktree 模式;点击「打开」可直接进入该任务详情。卡片保存在聊天历史中,重新打开对话仍可使用。

通过对话能控制的是任务的 Project、Worktree 模式和 Base ref。权限模式与沙箱覆盖仍只能由你在界面中设置,AI 不能自行放宽权限、降低沙箱或改写已经带 owner 权限覆盖的任务。

### 运行中的聊天体验

任务详情不内嵌消息列表。点击任意一条「运行历史」会直接进入对应的普通聊天界面,并定位到该次运行;在那里可以使用完整输入框、查看实时流式输出和继续对话。

已有对话里的 Scheduled 消息带计时器徽标,由系统管理,不能编辑、删除或强制插入。它与桌面、网页和 IM 发来的普通消息共享同一个持久 FIFO:较早消息先执行,后来的 Scheduled 运行会显示排队 / 等待,不会越过正在运行的 turn 或用户已经排队的内容。普通消息在支持的界面仍可选择「回复后发送」或显式插入;这些操作也必须服从当前可用的队首规则。

### 历史、徽标与未读

- 定时任务页提供任务列表、日历和跨任务运行历史。历史按**具体运行**定位,可以查看状态、耗时、结果、投递和 Worktree 信息。
- 也可以直接在对话里问:「上次那个日报任务为什么没跑成功?」AI 能读取该任务近几次运行的状态、耗时、错误和结果摘要来回答。要停掉正在执行的那一次,可以说「停掉正在跑的那个定时任务」——这只结束当前这次运行,未来排程不受影响;要停掉后续排程请说「暂停」。
- 列表搜索同时匹配任务名、描述和最近一次运行的错误或结果摘要;状态筛选里的「需要处理」会只留下还需要你处理的任务。出问题的任务在列表行上直接标出原因(连续失败自动禁用、最近一次运行失败、错过运行、投递目标失效),并给出对应入口:自动禁用可一键恢复,投递目标失效直接进编辑,其余打开运行历史。
- 新对话运行会打开对应普通对话;已有对话运行会定位到该次运行的确切目标消息,不会跳到同一对话里的最新一轮冒充本次历史。
- 消息上的计时器卡片会显示任务名,可展开创建时的原始提示并跳回任务;标题栏也会显示来源任务。任务已删除时保留「任务已删除」标记,不会丢掉历史。
- 模型创建任务时,对话里会留下一张任务卡片:任务还在就显示状态和下次运行并可跳转详情;最近一次运行失败时可以直接在卡片上「再次运行」;任务被删除后卡片会标记为已删除,并提供「复制为新任务」,按原来的配置打开一个新建任务草稿。
- 定时任务角标是普通会话已读状态的一个投影,不是第二套未读。打开并实际渲染 Scheduled 预览或普通对话后会推进同一个已读位置;归档会话不计入角标,同一会话里的多次运行只计一个未读会话。Dock / 托盘也会按普通会话口径反映这些未读。

### 停止、取消与删除

- **排队中**:在运行历史里取消会精确删除这一条 Scheduled 消息,不会影响其它运行或普通消息。
- **运行中**:在历史里取消,或在普通对话里点击 Stop,都只停止这一次运行。它不会暂停未来排程,也不需要为了下一次运行点击 Continue。
- **Global Stop**:全局停止会把尚未执行的 Scheduled 消息一起持久暂停;使用对应的精确 Continue 后才恢复排队,重启应用也不会绕过这个围栏。
- **删除任务**:删除是逻辑删除。任务不再触发、也不再投递,但运行日志和已经创建的普通 / 旧版会话会保留。仍在运行的 occurrence 会先走精确取消或安全拒绝删除。删除后仍可从对话里的任务卡片「复制为新任务」,用原配置重建一个任务。

兼容说明:旧版 `SessionLoop` 运行没有可持久定位的 `turnId`,因此运行中不显示 Stop;任务正在运行时删除也会安全拒绝,请等它终止后再操作。新建的普通对话运行和已有对话运行均支持精确取消。

### 把结果发到 IM

任务结果的最终文本可以发到一个或多个 IM 会话——先选渠道账号再选会话。

- **投递白名单**:目标必须是已记录的真实 IM 会话,防止被注入的 AI 把周期任务变成外泄通道。
- **前缀开关**(默认关):成功投递时加 `[Cron] 任务名` 前缀,方便区分投到同一群的多个任务。
- 创建 / 修改时会验证账号、渠道和会话;账号被禁用、删除、信息过期或目标失效时会阻断预检或安全跳过投递,不会猜测发送。

### 每个任务的设置(仅所有者可设)

| 设置项 | 默认 | 说明 |
| --- | --- | --- |
| Agent / 项目 | 自动 / 无 | 仅新对话任务可设;已有对话任务跟随目标对话的 live 配置 |
| 权限模式覆盖 | 跟随 Agent | 该任务用标准 / 智能 / YOLO;**只能在界面里设,AI 工具不能改**(防提权) |
| 沙箱模式覆盖 | 跟随 Agent | 选非「关闭」需要 Docker,不可用则终止本次运行、绝不裸跑 |
| 超时覆盖 | 用全局 | 让长任务声明自己的预算,而不用抬高全局值 |
| 最大失败次数 | 5 | 连续失败达此值自动禁用(0 = 永不自动禁用) |

任务连续失败达到上限会**自动禁用并弹专属通知**;基础设施类失败(会话没起来)不计入。

### 常见状态与处理

| 状态 / 现象 | 含义与处理 |
| --- | --- |
| Preparing / Queued | occurrence 已被可靠记录,正在准备或等待更早消息 / 全局并发槽;无需重复点击立即运行 |
| Running | 模型或工具正在执行;可对支持精确取消的运行使用 Stop / 取消 |
| Completing | 模型已结束,系统正在收尾 Worktree、台账或投递;此时不再接受 Stop |
| Cancelled | 只取消了本次 occurrence,未来排程仍有效 |
| Paused / Needs attention | 目标对话、项目、Worktree 或投递配置需要处理;修复后显式恢复任务 |
| Task deleted | 任务已停止触发,历史与 retained 资源仍可查看 / 清理 |

无效或已归档的已有对话目标会让循环任务暂停,而不是每个周期反复制造错误。基础设施类失败不会计入连续失败上限;一次性任务在模型真正开始前遇到基础设施错误时会按安全规则重试,取消则不会被误记成失败。

### 全局设置(设置 → 定时任务,中风险)

| 设置项 | 默认值 | 作用 |
| --- | --- | --- |
| 最大并发 | 5 | 调度器全局并发上限(0 = 不限) |
| 全局超时 | 0 | 每次运行的时间预算(0 = 不加超时) |
| 补跑窗口 | 300 秒 | 一次性任务错过后的补跑窗口(0 = 严格不补跑) |

## 9.5 自我唤醒(schedule_wakeup)

这是 AI 的一次性「N 秒后把我叫回当前会话续跑」的能力,和定时任务不同:

| 维度 | 自我唤醒 | 定时任务 |
| --- | --- | --- |
| 语义 | AI 主动「过一会儿叫我回来」 | 独立的计划任务 |
| 次数 | **一次性** | 一次或循环 |
| 回到哪 | 当前会话 | 新普通对话,或你指定的现有对话 |
| 适用 | 短周期临时等待(等某个任务跑完) | 长周期 / 循环 / 需要投递的任务 |

延迟范围 10 秒到 24 小时(默认上限,可在设置里最高调到 7 天),每个会话最多挂 5 个待唤醒。
