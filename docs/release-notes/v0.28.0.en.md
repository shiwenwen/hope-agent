# Hope Agent 0.28.0 — Hardening Remote Use and Deployment

> [简体中文](https://github.com/shiwenwen/hope-agent/blob/v0.28.0/docs/release-notes/v0.28.0.md) · **English**

> Release date: 2026-08-03

> See [`CHANGELOG.md`](https://github.com/shiwenwen/hope-agent/blob/v0.28.0/CHANGELOG.md#0280---2026-08-03) for details.

This release is about staying safe and stable away from the local desktop. Running Hope Agent as a server, reaching it from a browser, connecting it to Telegram, and deploying it in Docker are all hardened: authentication is now a single Owner Token that is no longer persisted to disk or placed in URLs; closing the browser no longer interrupts a running conversation; Telegram can point at your own API address; and Docker deployments can use the isolated sandbox. Desktop also picks up fixes for update progress and the new-folder permission flow.

## Added

- **Telegram can point at your own Bot API address**: when adding or editing a Telegram account you can enter a Bot API root you control, or leave it blank to keep the official endpoint. This suits networks that cannot reach the official API, or your own reverse proxy. The connection test uses the address you typed before saving, so a wrong or unreachable value fails clearly instead of silently falling back to the official endpoint. `socks5` proxies are supported.

## Changed

- **Authentication is now a single Owner Token**: same-origin browser login exchanges the token for a protected session credential and then discards it, while split-origin remote access holds it only in memory — the token is no longer persisted to disk or placed in URLs. Remote WebSocket and file previews use short-lived, scope-limited tickets. Plaintext tokens left in old configs and backups are migrated into a separate credentials file and cleaned up automatically during upgrade. After you save or rotate the token, the current page reconnects on its own instead of locking you out at the login screen.
- **Background activity shows readable names**: the composer and Workspace no longer surface internal identifiers like `subagent:batch`; batch subagent work now appears as a proper task-group label.
- **The subagent list is cleaner**: the repeated branch icon on every row is gone and the title leads each row; global search still keeps the type icon so you can tell session types apart in mixed results.

## Fixed

- **Closing or refreshing the browser no longer interrupts a running conversation**: a conversation started from a browser (or over the LAN) is now owned by the server and keeps running — closing the page just removes an observer. On reconnect or refresh the exact turn state comes back without re-sending your message, and pending tool approvals are preserved for you to pick up again.
- **Docker deployments can use the isolated sandbox**: even without a Docker CLI inside the container, a mounted Docker socket is enough to detect the daemon, and a missing socket or insufficient permission is reported clearly. Container deployments now support the `isolated` mode that uploads a bounded copy of the workspace into an anonymous volume; other modes that depend on host path mapping are safely refused instead of running unsandboxed.
- **Stopping is more reliable**: Desktop Stop, web Stop, IM `/stop`, and global stop all go through the same logic, so a turn is cancelled whether it is waiting for approval, waiting for your input, running tools, or running subagents. Partial output already produced is kept and marked as interrupted, and starting a new conversation afterward is no longer disturbed by the previous turn's cleanup.
- **Web-mode Agent settings and similar pages no longer crash**: in web mode, Agent settings, system prompts, logs, and Skills pages crashed because their response shape differed from the desktop transport; these are now consistent.
- **Desktop auto-update download progress is fixed**: downloads show a real percentage throughout, and show a clear indeterminate state instead of sitting at 0% when the server does not report a total size. Update checks from different entry points no longer collide into an install failure, and turning off update notifications no longer silently re-downloads the whole installer each round.
- **Creating a folder no longer starts without permission**: the server-side directory picker now starts from your own home directory (with a Home shortcut) instead of the root, so an ordinary user's first new-folder attempt no longer lands in a system location with no write access. Read-only or unwritable locations get actionable guidance.

## Upgrade notes

This release performs one automatic credential migration on startup: if an old config holds a plaintext Owner Token, it is moved into a separate credentials file and removed from the current config and from config backups. This needs no action from you and changes no other settings.

If you run in remote / server mode: after updating, the browser goes through a fresh login to obtain a protected session credential; after you save or rotate the token, the current page reconnects instead of being kicked back to login.
