# Hope Agent 0.29.0 — IM Messages Are Queued, Not Dropped

> [简体中文](https://github.com/shiwenwen/hope-agent/blob/v0.29.0/docs/release-notes/v0.29.0.md) · **English**

> Release date: 2026-08-04

> See [`CHANGELOG.md`](https://github.com/shiwenwen/hope-agent/blob/v0.29.0/CHANGELOG.md#0290---2026-08-04) for details.

This release fixes one long-standing IM problem: when a message arrived while its session was still answering the previous one, the new message could be turned away as "busy" — the backend produced a reply, but the IM side never received it. That path now works.

## Fixed

- **Sending an IM message while the session is busy no longer loses the reply**: if an IM message arrives while its session is still answering the previous one, it is no longer dropped as "busy." It is queued by the backend and processed in the order you sent it, one at a time, and every queued message is guaranteed to get its own reply. Restarting the app does not lose queued messages — they resume automatically in their original order. If you explicitly stop the current turn, queued messages are held (also not lost) and resume in order only when the next IM message arrives — stopping does not auto-continue them; a new message wakes the queue. What the IM client receives, the streaming output, and the final state stay consistent with the desktop / web view; queued messages are visible in the desktop pending list but are backend-owned and read-only.

## Upgrade notes

There is no config migration in this release; update directly.
