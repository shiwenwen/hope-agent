# Hope Agent 0.36.0 — More consistent conversations across every entry point

> [简体中文](https://github.com/shiwenwen/hope-agent/blob/v0.36.0/docs/release-notes/v0.36.0.md) · **English**

> Released: 2026-08-26

> See [`CHANGELOG.md`](https://github.com/shiwenwen/hope-agent/blob/v0.36.0/CHANGELOG.md#0360---2026-08-26) for the full list.

This release focuses on conversation reliability. Whether a request starts in the desktop app, Server, ACP, an IM channel, a scheduled task, or a sub-agent, Hope now uses the same execution lifecycle for starting, stopping, resuming, persistence, and completion. This reduces inconsistent outcomes when a request must recover from an interruption or failure.

## Changed and fixed

- **Stop and completion states are more consistent**: Every runtime mode now follows the same turn boundaries, so cancellation, failure convergence, and final status reporting no longer depend on separate paths that can drift apart.
- **Recovery across entry points is more reliable**: Requests that must persist or continue across process boundaries share the same admission and completion rules, reducing the risk of duplicate execution or lost state.
- **Non-desktop entry points stay aligned with the main conversation**: Server, ACP, IM, scheduled tasks, and sub-agents use the same core execution constraints as the desktop conversation.

## Upgrade notes

Update directly. No data migration or settings changes are required.
