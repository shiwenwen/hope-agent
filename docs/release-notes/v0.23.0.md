# Hope Agent 0.23.0 — Hooks 官方协议对齐、子 Agent 续跑与对话归档

> **简体中文** · [English](https://github.com/shiwenwen/hope-agent/blob/v0.23.0/docs/release-notes/v0.23.0.en.md)

> 发布日期：2026-07-25

> 详见 [`CHANGELOG.md`](https://github.com/shiwenwen/hope-agent/blob/v0.23.0/CHANGELOG.md#0230---2026-07-25)。

v0.23.0 的主线是「让自动化更靠得住」：hooks 与 Claude Code 官方协议做了一次字段级对齐，并落地 6 个真正能阻断的事件，Claude Code 生态里的社区脚本基本可以直接搬过来用；子 Agent 有了稳定线程，完成、模型失败、超时乃至应用被强退之后都能在原来的子对话里续跑；对话新增可逆归档，侧边栏不再需要靠「删除」来清场。

## 亮点

- **Hooks 与 Claude Code 官方协议字段级对齐，6 个可阻断事件落地**：payload 字段名整体对齐官方（`SessionEnd.reason`、`Notification.type`、`StopFailure.error_type`、`FileChanged.file_path`、`SubagentStart` / `SubagentStop.agent_type` 等），`PostToolBatch` 携带官方 `tool_calls[]`、`Stop` 与 `SubagentStop` 携带 `last_assistant_message`；输出侧 `updatedToolOutput`（可改写工具结果做脱敏）与 `decision.behavior` 已接入生效；matcher 支持 `,` 分隔、正则改为非锚定；payload 新增 `effort.level` 与 `prompt_id`，脚本可按「同一轮对话」分组。同时 `Stop`、`PostToolBatch`、`TaskCreated` / `TaskCompleted`、`UserPromptExpansion`、`PermissionRequest` 六个事件真正可以阻断——`Stop` 支持官方的 block-to-continue（注入反馈让模型再工作一轮，带 3 次上限），`PermissionRequest` 可自动拒绝审批（只认 deny，hook 的 allow 不会绕过用户或 strict 模式）。
- **子 Agent 线程可续跑，新增 `send` 统一跟进入口**：子 Agent 现在是一条稳定线程而不是一次性运行。`send` 会按当前状态自动选择「插话」（运行中，消息已持久化、重启不丢）还是「续跑」（已结束），完成、模型失败、超时或进程中断的子 Agent 都能在同一子对话里开新一轮尝试，复用原有对话与工作目录；用户手动停止、审批拒绝、父级或 Workflow 取消这几类终态一律不允许续跑，只能重新派发。应用被强退后，正在跑的子 Agent 不再笼统标成「出错」，而是显示「已中断」并把结果投递给主 Agent 由它决定是否续跑。Workflow V5（新脚本默认）同步支持显式 `resumeAgent` 与崩溃恢复，未处理的失败子任务不会再被静默算作 Workflow 成功。
- **对话支持归档**：侧边栏、项目、定时任务运行历史、知识空间与设计空间的对话都可一键归档。归档后对话立即从日常列表、全局搜索、未读角标和项目会话计数里消失，同时清除置顶并把当前内容标记为已读，但消息、附件、项目与 Agent 归属都完整保留。设置里新增「已归档对话」页作为唯一的跨类型管理入口，按每页 50 条加载，可对已加载的记录搜索标题 / Agent / 项目名并按对话类型与项目筛选，随时一键恢复——搜索与筛选目前只作用于已加载的分页，归档条数多时需要先「加载更多」才能命中较早的对话。无痕对话不可归档（仍是关闭即焚）；归档也不等于 IM 免打扰——已绑定 IM 聊天的对话一旦收到新的入站消息就会自动恢复到活跃列表。
- **Windows Docker 沙箱可直接使用 WSL 内的 Docker Engine**：宿主机没装 / 没起 Docker Desktop 时，Hope Agent 会探测默认 WSL 发行版里的本地 Docker daemon，并自动切到 WSL 后端执行沙箱命令；设置页会按检测到的 WSL / Engine 状态切换提示，把 Windows 的安装主入口从 Docker Desktop 换成 WSL 内的 Docker Engine。远程 Docker Context 不会被隐式采用，WSL 路径与 Docker Socket 挂载继续 fail-closed，超时或取消也会可靠清理容器。

## 升级提示

- **hooks 脚本有两处破坏性变化**：一是 payload 字段改用官方名后，旧名已彻底移除、没有兼容别名——按本项目旧字段名（`.source` / `.path` / `.notification_type` / `.content`）写的脚本会静默读到 null，需要改成官方名（`.reason` / `.file_path` / `.type` / `.task_name`）。二是 `PermissionRequest` / `PermissionDenied` 的 matcher 目标从命令串改成了工具名（`Bash` / `Write` 等官方别名自动归一到内部名），只有调用点没给出工具名时才回退命令串——按命令模式写的存量 matcher（如 `"rm -rf.*"`）不再触发，需要改成工具名，或用 `if` 规则去匹配入参。另外含 `^前缀` 的正则 matcher 语义从「整串匹配」变成了「前缀匹配」（对齐官方 unanchored）。
- **删除对话的入口移到了「设置 → 已归档对话」**：侧边栏悬停按钮与右键菜单现在只有「归档」，设计空间对话历史原有的两步删除也改成了归档。永久删除只在归档管理页提供，需要二次确认且不可撤销。
- **自动更新的后台检查默认改为每 30 分钟一次**（原先 12 小时）：新版发布后能更快收到提示，代价是默认向发布服务器的检查频率提高了。桌面与 headless 共用这项配置，嫌频繁可在「关于」页把间隔调大（现在支持小数，范围 0.5–168 小时）。安装与重启仍然始终需要你确认。

## 变更

- **全局选中态更醒目，标签与 Tab 反馈统一**：此前「当前选中」普遍用半透明浅底，在暗色主题或密集列表里几乎和鼠标悬停、页面底色分不出来，同一类控件在不同页面还各有一套写法。现在侧栏视图入口、会话 / 笔记 / 文件列表、卡片、模式切换与运行记录一律用实色底表示选中；单选与多选标签共用同一套反白样式并保留原图标，未选中标签也有明确的悬停反馈；Tab 选中面去掉阴影，切换时平滑滑到新标签（系统开启「减少动态效果」时直接切换）。服务商模板与自定义向导的「返回」从底部移到标题栏左上，底部只留「下一步」/「保存」，减少误点。
- **侧边栏的更新标记改为可点击按钮，低频入口按窗口高度收纳**：底部 Logo 上的更新标记从不可点的呼吸圆点换成「更新」按钮——把更新弹窗关掉或忽略之后仍可随时从这里重新打开，此前一旦 dismiss 就只能重启应用才会再出现。低频入口会按窗口高度分级收进「更多」菜单，避免窗口缩小时 Logo 被裁剪或入口突然空出大段空间。
- **子 Agent 面板按线程折叠，`kill_all` 收窄到自己派发的子 Agent**：续跑不再刷出多行，同一子 Agent 只占一项并显示累计尝试次数，可在历史尝试之间切换，详情面板新增线程 ID、尝试序号与终止原因；分区计数口径随之从「运行次数」变为「线程数」。模型调 `kill_all` 时也不再连带打断同一会话里由 Workflow、Team 或内部流程派发的子 Agent。

## 修复与稳定性

- **消息「在新会话中继续」的分支边界修正**：在自己的某条提问上分支，新会话现在只复制这条提问之前的历史，提问正文、附件与文件 / 消息引用会还原进新会话输入框并自动聚焦，改完再发即可——此前这条提问会被直接复制成历史里既发不出去也改不了的死消息，想换个方向只能重新打字。被中途停止、没有最终回复行的助手回合现在也能分支，而定时触发、子 Agent 回执、Plan 执行与审阅留言、IM 入站这类消息不再显示分支按钮。普通对话与设计空间对话同样生效。
- **Linux 下滚动聊天窗口不再周期性发虚**：主窗口与 QuickChat 窗口在 Linux 关闭透明（Windows 早有同款先例），Linux 桌面版的全部毛玻璃表面统一降级，并补充 Noto 字体栈；QuickChat 窗口随之在 Linux 上改为方角。Windows 主窗口也找回了丢失的启动居中。
- **Docker 沙箱不再因为 `docker` 命令不在应用 PATH 里就报「未安装」**：daemon 可直连时即视为可用（执行本身走 Docker API，不需要 CLI），修好了 macOS / Linux 上「Docker 明明在跑，沙箱工具却被拒绝执行」的情况。
- **MCP 长任务工具的后台执行现在真的生效**：声明 `taskSupport` 的 MCP 工具此前虽然在 schema 里露出 `run_in_background`，实际调用却被静默同步执行；现在会按服务器声明正确进入后台任务并支持自动后台。
- **审批类 hook 现在能看到工具参数**：`PermissionRequest` / `PermissionDenied` 补齐了官方 `tool_input` 与 `tool_use_id`，脚本可以直接判 `.tool_input.command`，不必再从截断的命令描述里猜。注意这里给的是权限引擎真正评估的那份入参，所以有 PreToolUse hook 改写入参时会与 PreToolUse 自己的 payload 不同。
- **没配 hook 时不再有额外开销**：同步 hook 触发点新增一道预检，未配置对应事件时直接返回，省掉此前每次触发都会做的一次会话查库（`FileChanged` 这类高频事件受益最明显）。
