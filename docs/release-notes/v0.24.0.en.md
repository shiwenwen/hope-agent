# Hope Agent 0.24.0 — Desktop Pets and Inline Prompt Editing

> [简体中文](https://github.com/shiwenwen/hope-agent/blob/v0.24.0/docs/release-notes/v0.24.0.md) · **English**

> Release date: 2026-07-27

> See [`CHANGELOG.md`](https://github.com/shiwenwen/hope-agent/blob/v0.24.0/CHANGELOG.md#0240---2026-07-27) for details.

v0.24.0 moves "what is it doing right now" onto your desktop: a new desktop pet lives above your other windows and projects your main conversations' running, needs-input, failed, and unread-complete states as bubbles you can reply, stop, answer, and approve from — and it is compatible with your existing Codex pet packages. The other half is about the conversation itself: your last prompt can now be edited in place and resent, without forking or retyping.

## Highlights

- **A Codex-compatible desktop pet**: enable it from the toggle at the bottom of the sidebar or from "Settings → Desktop pets" (off by default), and a transparent pet window takes up residence on your desktop. It projects four conversation states as bubbles — running (with a live streaming preview), needs input, failed, and unread complete — showing just a count badge on the pet's corner when collapsed, and one capsule bubble per conversation when expanded. From a bubble you can send a quick reply or stop the current task, and `ask_user_question` prompts and tool approvals get their own compact cards, so you can handle them without returning to the full conversation. Clicking a bubble's body navigates back to that conversation, correctly restoring regular chats, Knowledge Space threads, and Design Space threads by type. The pet itself can be dragged anywhere, right-click gives you "Settings / Close", and a single click brings up the main window.
- **Pet packages interoperate with Codex, and every import asks you first**: import by scanning an existing Codex installation directory, by dropping a folder / zip / sprite sheet, by pasting a `codex://` or `hope-agent://` link, via the `hope-agent://` system protocol, or by generating one from scratch in Settings. Every path goes through the same three steps — preview, validate, confirm — so nothing is ever installed or enabled silently, and an installed pet can be exported as a minimal Codex-compatible zip. Deletion goes to a trash folder and can be undone within 10 minutes. On first use, a one-time, non-modal discovery hint appears next to the sidebar's easter-egg icon; it never steals focus.
- **The last prompt can be edited in place and resent**: once the turn's reply has finished or you have stopped it, hover your own last prompt to edit it inline, then send to re-run that turn with the new content. Attachments, Goal metadata, and the provider's base context are preserved as-is, and the tail of the conversation is rewritten in a single atomic transaction, so old and new messages never end up interleaved. Previously, changing one sentence meant forking the conversation or retyping it.

## Upgrade notes

- **The desktop pet is off by default, and the overlay is desktop-only.** Turn it on at the bottom of the sidebar or in "Settings → Desktop pets". The HTTP / Web surface can manage the pet library and pick which pet is selected, but it cannot toggle the overlay — the corresponding window commands explicitly report that it is desktop-only.
- **Editing and resending discards everything after that prompt and does not roll back files.** When you send the edited content, the replies and any later messages after that prompt are removed and the turn is re-run with the new content — but file changes the previous turn already wrote to disk are **not** undone. The editor tells you so; use Git or similar if you need to revert files. Editing is also unavailable while a reply is streaming, while messages are queued, on slash-command messages, and in the cron and sub-agent session viewers.
- **The pet only projects first-party main conversations.** The main chat, QuickChat, Knowledge Space, Design Space, and pet quick replies show up on the pet; side queries, automation, context compaction, memory, cron, IM, ACP, sub-agents, and background jobs do not. Titles and previews for incognito conversations are always redacted, and calls to the public `/api/chat` are never adopted just because they passed a `uiSurface`.

## Changed

- **The Linux visual downgrade from 0.23 has been reverted — frosted glass and system fonts are back.** To mitigate text blurring periodically while scrolling on Linux, 0.23 globally disabled `backdrop-filter` and forced a Noto font stack. The reporter could still reproduce the blur on KDE/KWin Wayland at 1.0 scaling, which invalidates the "transparent window + frosted glass + fractional scaling" assumption behind that change — it cost Linux desktop builds their look for nothing. This release restores frosted glass and system font selection on Linux. The blurring itself is **not fixed**: the more likely root cause is WebKitGTK / wry not keeping the window size and the WebView's render size in sync under Wayland, tracked upstream at [wry #1727](https://github.com/tauri-apps/wry/issues/1727). The narrower Linux window-transparency mitigation and the Windows startup-centering fix from 0.23 are unaffected and remain in place.
