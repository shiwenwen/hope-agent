# Hope Agent 0.30.0 — Native replies in chat apps, Nori, and `/fork`

> [简体中文](https://github.com/shiwenwen/hope-agent/blob/v0.30.0/docs/release-notes/v0.30.0.md) · **English**

> Released: 2026-08-07

> See [`CHANGELOG.md`](https://github.com/shiwenwen/hope-agent/blob/v0.30.0/CHANGELOG.md#0300---2026-08-07) for the full list.

This release went into two things. First, making Hope Agent look like a proper native bot in Slack and Telegram instead of a wall of plain text. Second, giving you a way out when a conversation reaches a fork in the road — instead of choosing between wrecking the one you have and starting over, `/fork` just copies it and you keep going. The desktop pet is now Nori, and connecting to a remote server can finally tell you when that server has an update.

## Added

- **`/fork`: copy the current conversation and continue in the copy**: When you want to try a different direction but don't want to lose where you are, type `/fork`. Everything settled so far is copied into a new session and you carry on there; the original stays exactly as it was, so you can go back any time. Desktop, web, Quick Chat, Design Chat, and chat-app surfaces all switch to the copy automatically. If the switch doesn't take on the chat-app side, you'll be told to switch with `/session` — the forked conversation is never lost.
- **Slack and Telegram now use each platform's own reply style**: A reply updates in place as it's generated instead of arriving in fragments. Slack shows plans, task progress, and buttons you can actually click; Telegram gets rich text, images, and buttons. Where a platform genuinely doesn't support something, it falls back to plain text safely — and when delivery is uncertain, it would rather not resend than have you receive the same message twice.
- **Remote connections can prompt for server updates**: When you connect to a machine running Hope Agent from a browser or a remote desktop, you can now see that server's update status, check for updates, confirm an install, and watch its progress. Whether you get prompted at all, and whether checking is allowed, is up to that server's own configuration. The manual check on the About page stays.

## Changed

- **The built-in desktop pet is now Nori**: It follows your cursor when idle, and the jump, run, and "reviewing" animations were redone. If you were already using the built-in pet, it simply becomes Nori after updating — nothing to reconfigure.
- **New pets use the newer artwork by default**: Newly created pets turn to follow your cursor and move more smoothly. If you need the older style, you can still pick it explicitly when creating. Existing older pets in your library can generate a newer copy in one click — **the original is left untouched**; the copy is switched to only after it installs, and you can keep using the old one or export it.

## Fixed

- **MCP tools that wouldn't work in new conversations**: The connection test passed and the dynamic tools showed up in settings, but in a new conversation the model could only reach resources and prompts — never the actual tools. Fixed. Settings now offers three tool-loading strategies to choose from, and servers that start on demand no longer get stuck needing to know a tool's name before they can find it.
- **Messages sent while a chat is busy no longer go unanswered**: When a chat-app message arrives while its bound conversation is still replying to the previous one, it's no longer dropped as "busy". It queues up and each message gets its own reply, in the order you sent them. Restarting the app doesn't lose queued messages. If you manually stop the current turn, queued messages are kept and resume in order **when the next message arrives** — stopping won't let them run on by itself; it takes one more message to wake them.

## Upgrade notes

No configuration migration in this release — just update.

The switch to Nori happens on its own. To use something else, pick a different pet in the pet library in Settings.
