# Hope Agent 0.23.0 — Claude Code Hooks Parity, Resumable Sub-Agents, and Conversation Archiving

> [简体中文](https://github.com/shiwenwen/hope-agent/blob/v0.23.0/docs/release-notes/v0.23.0.md) · **English**

> Release date: 2026-07-25

> See [`CHANGELOG.md`](https://github.com/shiwenwen/hope-agent/blob/v0.23.0/CHANGELOG.md#0230---2026-07-25) for details.

v0.23.0 is about making automation dependable: hooks got a field-level realignment with the official Claude Code protocol plus six genuinely blocking events, so community scripts from the Claude Code ecosystem largely work here as-is; sub-agents now live on a stable thread and can be resumed in their original sub-conversation after completing, failing, timing out, or even after the app is force-quit; and conversations can be archived reversibly, so the sidebar no longer needs deletion to stay tidy.

## Highlights

- **Field-level parity with the official Claude Code hooks protocol, plus six blocking events**: payload field names now match the official ones (`SessionEnd.reason`, `Notification.type`, `StopFailure.error_type`, `FileChanged.file_path`, `SubagentStart` / `SubagentStop.agent_type`, and more); `PostToolBatch` carries the official `tool_calls[]`, and `Stop` / `SubagentStop` carry `last_assistant_message`. On the output side, `updatedToolOutput` (rewrite a tool result, e.g. to redact it) and `decision.behavior` are wired up and effective; matchers accept `,` as a separator and regexes are now unanchored; payloads gained `effort.level` and `prompt_id`, so scripts can group events by turn. Six events are now genuinely blocking — `Stop`, `PostToolBatch`, `TaskCreated` / `TaskCompleted`, `UserPromptExpansion`, and `PermissionRequest`. `Stop` supports the official block-to-continue (inject feedback and let the model work another turn, capped at 3), and `PermissionRequest` can auto-deny an approval (deny only — a hook's allow never bypasses you or strict mode).
- **Sub-agent threads can be resumed, with `send` as the single follow-up entry point**: a sub-agent is now a stable thread rather than a one-shot run. `send` automatically picks between steering (while running — the message is now persisted and survives a restart) and resuming (once finished); a sub-agent that completed, hit a model failure, timed out, or was interrupted can start a new attempt in the same sub-conversation, reusing the original conversation and working directory. Terminal states from a manual stop, a denied approval, or a parent / Workflow cancellation are never resumable and must be dispatched afresh. After a force-quit, a sub-agent that was running is no longer lumped in as "error" but shows as "interrupted", and its result is delivered to the main agent, which decides whether to resume. Workflow V5 (the default for new scripts) gained explicit `resumeAgent` and crash recovery, and an unhandled failed sub-task is no longer silently counted as workflow success.
- **Conversations can be archived**: conversations in the sidebar, in projects, in scheduled-task run history, in the Knowledge Space, and in the Design Space can all be archived in one click. An archived conversation immediately disappears from everyday lists, global search, unread badges, and project conversation counts — it is also unpinned and marked read — while its messages, attachments, project, and Agent association are kept intact. A new "Archived conversations" page in Settings is the one cross-type management surface: it loads 50 at a time, and searching by title / Agent / project name and filtering by conversation type and project apply to what is currently loaded — with a large archive you may need to "Load more" before an older conversation can be matched. Restoring is one click. Incognito conversations cannot be archived (they remain burn-on-close), and archiving is not an IM mute — a conversation bound to an IM chat is restored automatically as soon as a new inbound message arrives.
- **The Windows Docker sandbox can use Docker Engine inside WSL directly**: when Docker Desktop isn't installed or isn't running on the host, Hope Agent probes for a local Docker daemon in the default WSL distribution and automatically switches to the WSL backend to run sandboxed commands. The settings page switches its guidance based on the detected WSL / Engine state and makes Docker Engine on WSL the primary install path on Windows. Remote Docker contexts are never adopted implicitly, WSL paths and Docker socket mounts stay fail-closed, and containers are reliably cleaned up on timeout or cancellation.

## Upgrade notes

- **Two breaking changes for hook scripts.** First, now that payload fields use the official names, the old names are gone entirely with no compatibility aliases — scripts written against this project's old field names (`.source` / `.path` / `.notification_type` / `.content`) will silently read null and must switch to the official names (`.reason` / `.file_path` / `.type` / `.task_name`). Second, the matcher target for `PermissionRequest` / `PermissionDenied` changed from the command string to the tool name (official aliases like `Bash` / `Write` are normalized to internal names), falling back to the command string only when the call site doesn't supply a tool name — existing matchers written as command patterns (e.g. `"rm -rf.*"`) no longer fire and must be rewritten as tool names, or moved to an `if` rule that matches the arguments. Additionally, a matcher regex with a `^prefix` now means "prefix match" instead of "whole-string match" (matching the official unanchored behavior).
- **Deleting a conversation moved to "Settings → Archived conversations".** The sidebar hover button and context menu now only offer "Archive", and the Design Space conversation history's old two-step delete became archive as well. Permanent deletion is available only on the archive management page, asks for confirmation, and cannot be undone.
- **The background update check now defaults to every 30 minutes** (it was 12 hours). You'll be notified of a new release sooner, at the cost of a higher default check frequency against the release server. Desktop and headless share this setting; if it's too frequent, raise the interval on the About page (fractional values are now allowed, in the range 0.5–168 hours). Installing and restarting still always require your confirmation.

## Changed

- **Selection states are clearer, and pill and tab feedback are unified.** Persistent selection previously used a translucent light background that was nearly indistinguishable from hover or the page background in dark mode and dense lists, and the same kind of control was styled differently on different pages. Now sidebar view entries, conversation / note / file lists, cards, mode switchers, and run records all use a solid background to indicate selection; single- and multi-select pills share one inverted style and keep their original icons, and unselected pills have clear hover feedback; the tab selection surface lost its shadow and slides smoothly to the new tab (switching instantly when the system's "reduce motion" is on). "Back" in the provider template and custom wizard moved from the footer to the top-left of the header, leaving only "Next" / "Save" at the bottom to reduce misclicks.
- **The sidebar's update marker is now a clickable button, and low-frequency entries collapse by window height.** The update marker on the bottom logo went from a non-clickable pulsing dot to an "Update" button — after you close or dismiss the update dialog you can reopen it from here at any time, whereas previously a dismissal meant restarting the app to see it again. Low-frequency entries progressively fold into the "More" menu as the window gets shorter, so the logo isn't clipped and entries don't leave a large gap.
- **The sub-agent panel folds by thread, and `kill_all` is scoped to the model's own sub-agents.** Resuming no longer produces extra rows: one sub-agent occupies a single entry showing its cumulative attempt count, with switching between past attempts, and the detail panel gained thread ID, attempt index, and terminal reason; the section count accordingly changed from "runs" to "threads". When the model calls `kill_all`, it no longer also interrupts sub-agents dispatched by Workflow, Team, or internal flows in the same session.

## Fixes & stability

- **Message "continue in a new session" now forks at the right boundary.** Forking from one of your own prompts copies only the history *before* that prompt and restores the prompt's text, attachments, and file / message quotes into the new conversation's composer with focus, so you can edit it and send — previously the prompt was copied in as a dead history message you could neither send nor edit, leaving you to retype it. Interrupted assistant turns with no final reply row can now be forked at all, while cron triggers, sub-agent results, plan execution and plan review comments, and inbound IM messages no longer show a fork button. This applies to both regular chats and Design Space threads.
- **Scrolling the chat window on Linux no longer blurs periodically.** Transparency is now off for the main window and the QuickChat window on Linux (Windows already had the same precedent), every frosted-glass surface is downgraded on Linux desktop builds, and a Noto font stack was added; the QuickChat window is consequently square-cornered on Linux. The Windows main window also got back its lost startup centering.
- **The Docker sandbox no longer reports "not installed" just because the `docker` command isn't on the app's PATH.** A reachable daemon now counts as available (execution itself goes through the Docker API and needs no CLI), fixing the case on macOS / Linux where Docker was clearly running yet sandboxed tools were refused.
- **Background execution for long-running MCP tools now actually takes effect.** MCP tools declaring `taskSupport` previously exposed `run_in_background` in their schema but were silently executed synchronously; they now correctly enter a background task per the server's declaration, including auto-backgrounding.
- **Approval hooks can now see tool arguments.** `PermissionRequest` / `PermissionDenied` gained the official `tool_input` and `tool_use_id`, so scripts can check `.tool_input.command` directly instead of guessing from a truncated command description. Note that this is the argument set the permission engine actually evaluates, so it differs from the PreToolUse payload whenever a PreToolUse hook rewrote the input.
- **No extra overhead when no hooks are configured.** Synchronous hook trigger points gained a pre-check that returns immediately when the event has no handler, eliminating the session database lookup that previously happened on every trigger (high-frequency events like `FileChanged` benefit most).
