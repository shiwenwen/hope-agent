# 项目自主运维自动化

本契约约束开发者维护的 Codex 项目自动化，与产品内的 [Cron 调度](cron.md) 分开。
任务触发、会话与权限继续由 Codex 管理；本层提供确定性的状态读取、去重、互斥、
归档校验和运维资产恢复，不新增 Provider 循环或产品权限旁路。

## 运行边界

`scripts/automation/control.py` 仅使用 Python 标准库。安装到用户明确授权的受控运行
目录后，读取同目录的 `policy.json`、`tasks.json` 和既有 `prepare.py`。
默认目录为 `~/.codex/automation-runtime/hope-agent`；配置仅登记本项目任务 ID。
Codex 调度数据库通过只读 SQLite URI 访问，不更新任务配置、会话或运行状态。
创建、修改和暂停自动化使用 Codex 原生工具。

所有源码研究、验证与实施仍先通过精确任务 ID 的 `prepare.py prepare`；失败保持关闭。
已停止且干净的失败快照可以按 helper 协议收尾或续跑，不能把生命周期 `completed`
当作报告或交付成功。受限会话不能借其他会话扩大文件权限。

## 四类运维职责

| 职责 | 业务终态与恢复条件 |
| --- | --- |
| 自动化自检与恢复 | 读取预期排程、原生会话终态、成功产物与环境状态；容量或临时网络失败有限退避，额度失败等待实际重置，权限和产品决策进入统一决策队列 |
| 依赖与模型生命周期快检 | 官方安全或退役证据、影响范围、主责与期限明确；机器人 PR 沿精确 head、普通检查、审查线程与受保护合并收口 |
| 产品回归巡检 | 主分支或稳定版变化后选现有普通烟雾夹具；仅使用合成数据，不读用户凭据或调用付费模型；完整专项评测不进入本巡检或 CI |
| 运维资产恢复验证 | 只备份允许列表内的任务配置、运行脚本、行动卡台账和归档，独立临时目录恢复并逐文件核对字节数和 SHA-256；不写生产位置 |

跨任务的问题以「来源专项 + 稳定行动卡 ID」去重，一个事项只有一个实施主责。
旧待决策状态须根据当前授权重评；既有方向内的兼容维护、本地确定性复现可执行，
真实账号、费用、用户数据、权限放宽、宿主软件升级与产品方向改变仍需明确合同。

## 轻量预筛查与写入互斥

`preflight pr|issue|main` 只读取 GitHub 实时元数据，不读取入口 checkout 作为源码基线。
PR 指纹包含精确 head/base、反馈时间、线程、检查、工作流审批状态与主分支规则；
Issue 指纹同时包含 PR 生命周期元数据，评论只保存摘要哈希，不保存正文。
分页不完整、API 失败或规则读取失败均停止，不返回伪造的无变化。

处理后通过 `acknowledge` 保存观察结论。`no-change`、`waiting`、`blocked` 退避六小时，
`handled` 两小时；观察已处理不表示业务已交付。摘要哈希或任务归属不符拒绝确认。

进入仓库写入、重验证或合并前用受管 run_directory 获取 `lease`。
同一仓库只有一个持有者；持有者可以幂等恢复和释放，其他任务返回 `writer_busy`。
不按超时抢占。孤儿租约必须核对原生会话、运行归属、Git 状态和在途 PR 后处理。
释放先于 `finish`；已关闭持有者可以按其精确身份释放，无需复活已删除的工作树。

## 归档与恢复

完整 JSON 保留 task_name、generated_at、baseline、scope、sources、changes、decisions、
action_items、evidence_gaps、no_material_change。读取端兼容已有索引并跟随其不可变
双文件，拒绝路径穿越、符号链接、日期不一致、字段缺失和疑似凭据。

`normalize-archives` 只将已验证完整内容提升到可变 LATEST，先备份旧索引，失败恢复
旧双文件，不修改历史报告、数据或成功标记。历史哈希和失败会话必须保留。

`recovery` 创建不可变允许列表副本和 manifest，在临时目录恢复并核对所有哈希。
允许列表包括行动队列、决策队列、依赖/回归进度及重试状态，不复制整个控制状态目录。
发现篡改、秘密、越界或读写失败时只保存失败记录，不更新最近成功恢复证据。
本地恢复验收不证明异地副本可用，不包含用户数据库、密钥、Git 元数据或生成缓存。

解码后的敏感 JSON 字段拒绝非空值，重复字段不丢弃。少量旧研究文档以 `authorization`
表示实验许可说明，使用用户批准实施时核验的完整文档 SHA-256 清单兼容，仅该字段
可保留；字节变化不再匹配清单，其他敏感字段及所有凭据格式/授权头检查继续执行。
新文档权限说明使用 `authorization_scope_note`，不复用凭据字段名称。

## 验证与排障

运行 `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts/automation -p 'test_*.py'`
验证归档一致性、历史保留、路径穿越、符号链接、篡改、凭据拒绝、归属和互斥。
文件锁使用 POSIX `flock` 或 Windows 字节锁；Windows 没有符号链接创建权限时，
仅相应实链夹具跳过，其余控制验证继续运行。
该普通单测在 pre-push 与既有 Lint job 中运行，不增加门禁名称或专项评测。

本机控制状态在受控运行目录的 `control-state/`；归档恢复证据在 `recovery/`。
`PENDING_REVIEW` 是收件箱状态，不能用作执行成功；自检须用原生 `read_thread`
读取准确终态。电脑关机或应用退出时同机自检也停止，全天候运行需要常在线宿主和
独立存活检测；其成本与部署目标不能从本地检查结果推断。
